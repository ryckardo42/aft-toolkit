⬇️ DET baixar — arquitetura completa

Como o AFT Toolkit baixa as notificações do DET pela API oficial, em segundos e sem navegador — o botão "⬇ baixar arquivos" do painel e a skill /aft-det-baixar. Nasceu em 21/08/2026, substituindo um fluxo por navegador automatizado que levava ~10 minutos por notificação.

A ideia em uma frase: com o crachá que a extensão Sync DET já empresta ao painel (o token de sessão do próprio site), o motor det_baixar.py busca na API oficial o PDF da notificação, o Relatório de Atendimento e os arquivos entregues pelo empregador — organizados por item no pacote NOTIFICACOES/<CODIGO> <dd-mm-aaaa>/ da OS — e ainda registra a visualização no DET, apagando o alerta amarelo da tela. O token nunca passa pela conversa do assistente.

2. O fluxo, passo a passo

  1. O AFT navega no DET logado; a extensão captura o token de sessão e o guarda no chrome.storage.local (validade ~30 min).
  2. O token chega ao servidor do painel e fica guardado em RAM até o exp real do JWT (nunca em disco). Dois caminhos: a extensão v3.0 empurra sozinha a cada navegação no DET (POST /api/det-token, canal leve, throttle 2 min) e o Sincronizar (/api/det-sync) também abastece. Durante o trabalho, o token está sempre pronto — sem clique.
  3. O download é disparado pelo botão "⬇ baixar arquivos" do cartão ou pela skill /aft-det-baixar. Os dois caem no mesmo POST /api/det-baixar {pasta, codigo}.
  4. O servidor valida a pasta (filha direta de OS ATIVAS, sem path traversal). Sem token fresco: 409 {token_expirado} com a instrução de sincronizar.
  5. O motor pesquisa a notificação pelo código (chave única), obtém o uid e resolve o pacote de destino (pasta_do_pacote).
  6. Baixa os 2 PDFs e, item a item, cada arquivo entregue. Idempotente: o que existe é pulado; rejeitado/dispensado vai para invalidados/.
  7. Registra a visualização no DET (GET do detalhe + GET de cada item — as mesmas chamadas do site ao abrir a tela): o triângulo amarelo se apaga.
  8. Grava a linha no Registro de atividades do memory.md (com backup) e o painel recarrega sozinho.
  9. Devolve o resultado: pacote, baixados, ja_existiam, movidos, itens, sem_arquivo, invalidados, visto_no_det, erros.

3. Endpoints da API do DET

Levantados no bundle público do front do DET (chunk 251) em 21/08/2026 — o front é a fonte primária quando um campo é ambíguo: baixar o index.html, achar o runtime.<hash>.js, montar a URL do chunk e procurar o serviço. Autenticação: Authorization: Bearer com o token de sessão do próprio AFT.

4. O pacote na pasta da OS

NOTIFICACOES/<CODIGO> <dd-mm-aaaa>/     ← data do PRIMEIRO download
├── notificacao-<CODIGO>.pdf
├── relatorio-atendimento-<CODIGO>.pdf    ← SEMPRE refrescado
├── historico-itens.md                     ← prorrogações/justificativas/status
├── canal-comunicacao/                     ← só quando há mensagens
│   ├── mensagens.md · <anexos> · historico-canal.pdf
└── item<N>_<descrição oficial>/
    ├── <arquivos entregues>
    └── invalidados/                       ← rejeitados/dispensados no DET
  • Downloads repetidos (entrega parcelada, prorrogação aceita) acumulam no mesmo pacote, sem duplicar.
  • Legados migram sozinhos: notificacao-<COD> (raiz ou NOTIFICACOES/) é renomeado ao padrão; PDF solto é movido para dentro.
  • Apelido do AFT (<COD> jornada) é respeitado; pacotes nunca são mesclados automaticamente.
  • Nomes saneados para valerem também no Windows; colisão ganha sufixo -2, -3…

5. Segurança

  • O token vive só na RAM do servidor do painel, com validade igual ao exp real do próprio JWT (menos 60s de margem) — nunca em disco, nunca no chat, nunca na skill. Reempurrar o mesmo token não estende nada além do que o DET concede.
  • O servidor só escuta 127.0.0.1 e valida a pasta contra path traversal.
  • 401/403 do DET limpa o cache e devolve 409 com a instrução ("clique em Sincronizar").
  • Falha no registro de visualização nunca derruba o download (visto_no_det: false).

6. Pendências e limites conhecidos

  • A sessão do DET dura ~30 min (o exp do JWT) e não tem refresh: quando vence, o AFT reloga no gov.br — isso é do governo, nenhuma mudança na extensão remove. O auto-push da v3.0 elimina o Sincronizar manual e os "token expirado" durante a sessão, mas não o login em si.
  • O canal de comunicação é somente leitura: responder e registrar ciência são atos do AFT, no site (os endpoints de escrita existem, mas ficaram de fora de propósito).
  • Reinício do serviço do painel zera o token: primeiro download depois de publicar pede novo Sincronizar (não é defeito).
  • det_baixar.py é importado pelo servidor: mexeu, reinicie o serviço (o publicar.py já reinicia).
